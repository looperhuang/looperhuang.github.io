抽象類別（Abstract Class）與介面（Interface）的差異

在物件導向程式設計中，抽象化可以透過兩種方式實現：抽象類別（Abstract Class） 與 介面（Interface）。
兩者都用來建立規範，但各自的用途、限制與適用場景不同。

1. 抽象類別 (Abstract Class)

抽象類別是一種不能被實例化的類別，通常作為其他相關類別的基底類別 (Base Class) 使用，目的是提供共同的結構和部分實現。
它可以包含：

🚀 核心特性

  • 類別成員: 可以包含抽象方法（無實作）、已實作的方法（具體邏輯）、成員變數（欄位）和建構子。
  • 繼承限制: 由於 C# 不支援多重繼承，一個類別只能繼承一個抽象類別。
  • 設計哲學: 專注於 is-a 關係（是一種），強調族群的共同基礎。

📌 適用場合

  • 你希望定義一組具有**共同狀態(欄位)和預設行為(已實作方法)**的子類別。
  • 你希望提供部分邏輯實作，並將特定功能留給子類別強制實作。

C# 範例

public abstract class Animal
{
    // 1. 可以包含成員變數 (欄位)
    public string Name;

    // 2. 必須被子類別實作的抽象方法
    public abstract void MakeSound();

    // 3. 可以包含已實作的方法 (共同邏輯)
    public void Eat()
    {
        Console.WriteLine("Eating...");
    }
}

2. 介面 (Interface)

介面是一份契約或規範，它定義了一組類別必須實作的方法、屬性或事件，但不包含任何實作細節（在傳統設計中）

🚀 核心特性

  • 行為契約: 介面主要描述一個類別「能做什麼」（can-do 關係）。
  • 成員限制: 傳統上不能有欄位或建構子。所有成員預設為 public。
  • 多重實作: C# 支援一個類別實作多個介面，解決了多重繼承的限制。

📌 適用場合

  • 你需要定義一組跨越不同類別層次（不相關類別）的統一行為規範。
  • 你需要一個鬆散耦合的設計，以便於擴展和測試（依賴注入）。

C# 範例

// 定義一個飛行的能力
public interface IFly
{
    void Fly();
}

// 定義一個奔跑的能力
public interface IRun
{
    void Run();
}

// 一個類別可以同時擁有多個能力 (多重介面實作)
public class SuperHero : IFly, IRun
{
    // 必須實作 IFly.Fly() 和 IRun.Run()
    public void Fly() { /* 飛行邏輯 */ }
    public void Run() { /* 奔跑邏輯 */ }
}

⚖️ 抽象類別 (Abstract Class) vs. 介面 (Interface)

特點 抽象類別 (Abstract Class) 介面 (Interface)
設計哲學 是一種類別的抽象，定義一組相關類別的共同基礎。 是一種行為的抽象，定義一個契約 (Contract)，規定必須具備的能力。
成員實作 可以包含具體實作的方法和抽象方法。 傳統上只能包含抽象方法（C# 8.0+ 支援 Default 實作）。
成員變數 可以包含任何類型的成員變數。 只能包含常數 (public static final)。
建構函式 可以有建構函式。 不能有建構函式。
多重繼承 不支援多重繼承 (一個類別只能繼承一個抽象類別)。 支援多重實作 (一個類別可以實作多個介面)。
使用時機 實現**「is-a」關係和程式碼重用**。 實現**「can-do」行為契約和多型**。
