Docker 學習筆記

發表於 2026-10-09 分類於 系統與維運
Docker 基本概念、容器、網路、資料持久化、Dockerfile、Compose 與常見問題整理

0. 基本概念

名詞 說明
Image（映像檔） 唯讀的應用程式範本，包含程式、執行環境與設定，由多個 layer 疊成
Container（容器） 由 image 啟動出來的執行實例；一個 image 可以啟動多個 container
Registry（倉庫） 存放與分享 image 的服務，例如 Docker Hub
Dockerfile 描述如何建出 image 的腳本
Volume 讓資料脫離 container 生命週期的持久化儲存
Network 讓 container 之間互相連線的虛擬網路

類比：image 像「類別（class）」，container 像「物件（instance）」。

docker version        # 確認 Docker 已安裝（Client 與 Server 都有輸出才代表 daemon 正在運行）
docker info           # 查看系統資訊（Storage Driver 等）
docker --help         # 指令說明；也可用 docker <指令> --help

💻 Windows／macOS 使用 Docker Desktop，container 實際跑在內部的 Linux VM（WSL2）中，所以文中的 /var/lib/docker/... 路徑位於 VM 內，不是在 Windows 的資料夾裡。

1. Images（映像檔）

docker pull <image>[:tag]     # 下載映像檔，未指定 tag 預設為 latest
docker images                 # 列出本機映像檔
docker rmi <image>            # 刪除映像檔（需先移除使用它的 container）
docker image prune            # 清除未被使用的懸空（dangling）映像檔
docker history <image>        # 查看映像檔每一層的內容與大小

💡 tag 請固定版本（如 postgres:17），避免用 latest，否則不同時間拉到的內容可能不同。

2. Container（容器）

docker run = docker create + docker start

docker run -d -p 8080:80 --name my-web --network my-net <image>
參數 說明
-d 背景運行（detached）
-p <主機埠>:<容器埠> 埠號映射，例如 8080:80
--name <name> 自訂 container 名稱
--network <network> 指定要加入的 network（network 必須已存在，見第 3 章）
-e <KEY>=<VALUE> 設定環境變數
-v <來源>:<容器目錄> 掛載 volume 或目錄（見第 4 章）
-it 互動模式並配置終端機（進入 container 時使用）
--rm container 停止後自動刪除（適合一次性測試）
--restart <policy> 重啟策略，常用 unless-stopped、always

⚠️ 忘記設定 -p 映射，就必須刪除 container 重建（已建立的 container 無法補設）。

📌 -p 的左邊是宿主機埠、右邊是容器埠；宿主機的埠不能重複使用。

常用管理指令

docker ps                     # 列出運行中的 container
docker ps -a                  # 列出全部（含已停止）
docker ps -qa                 # 只顯示全部 container 的 id（-q: quiet, -a: all）

docker stop <id | name>       # 停止
docker start <id | name>      # 啟動已停止的 container
docker rm <id | name>         # 刪除（需先 stop，或加 -f 強制）

docker logs [-f] <id | name>  # 查看 log（-f 持續追蹤）
docker exec -it <id | name> bash   # 進入 container（沒有 bash 就改用 sh）
docker inspect <id | name>    # 查看詳細設定（JSON）

docker cp <container>:<路徑> <本機路徑>   # 在 container 與本機之間複製檔案（反向也可）
docker stats                  # 即時查看 CPU／記憶體使用量
docker top <id | name>        # 查看 container 內的行程

📌 <id> 只需輸入前幾碼、不與其他 id 重複即可。docker stop 會先送 SIGTERM，等待約 10 秒後仍未結束才強制終止。

3. Network（網路）

同一個自訂 network 內的 container，可直接用 container 名稱互相連線。

docker network ls                                  # 列出 network
docker network create <network>                    # 建立 network
docker network connect <network> <container>      # 將既有 container 加入 network
docker network inspect <network>                   # 查看 network 詳細資訊（含成員）
docker network disconnect <network> <container>   # 將 container 移出 network
docker network rm <network>                        # 刪除 network（需無 container 使用中）

⚠️ 只有自訂 network 才支援用名稱連線；預設的 bridge network 不支援，container 之間只能用 IP。

常見 driver：bridge（預設，單機內的虛擬網路）、host（直接共用宿主機網路，不需 -p；Docker Desktop 上行為有差異）、none（無網路）。

4. 資料持久化

4.1 Container 的可寫層（writable layer）

每個 container 都有自己的可寫層，容器內寫入的檔案都存放在這裡。

docker run -d --name mynginx nginx   # 先建立並啟動 container
docker exec -it mynginx bash   # 進入 container
echo hello > /tmp/test.txt     # 建立檔案並寫入 hello
cat /tmp/test.txt              # => hello
exit                           # 離開 container

docker stop mynginx            # 停止
docker start mynginx           # 重新啟動
docker exec mynginx cat /tmp/test.txt   # 檔案還在

docker rm -f mynginx           # 刪除 container
# => 可寫層一併消失，檔案也就不見了

結論：可寫層的生命週期跟著 container 走。資料庫這類需要長期保存的資料，不適合放在這裡：

  • container 可能被刪除，資料會跟著消失
  • 頻繁寫入可寫層，效能較差

→ 改用 Volume 或 Bind Mount。

📌 補充：可寫層的檔案其實仍存放在宿主機上，實際位置依 Storage Driver 而異。
例如使用 overlay2 時，位於 /var/lib/docker/overlay2/<id>/diff；
使用 containerd image store（overlayfs snapshotter）時，位於 /var/lib/docker/rootfs/overlayfs/<container id>。
這些路徑不建議手動修改。

4.2 Docker Volume

由 Docker 管理的持久化儲存空間：在宿主機上建立一個獨立的資料目錄，再掛載進 container。

docker volume create <name>        # 建立 volume
docker volume ls                   # 列出 volume
docker volume inspect <name>       # 查看詳細資訊（含 Mountpoint）
docker volume rm <name>            # 刪除 volume（不可有 container 使用中）
docker volume prune                # 清除未被使用的 volume
  • 實際資料目錄預設位於 /var/lib/docker/volumes/<name>/_data
  • 就是一般的資料目錄，不是 LVM 之類的區塊裝置
  • 即使 container 被刪除，volume 仍然保留

範例：用 Volume 保存 PostgreSQL 資料

docker pull postgres:17

docker run -d --name postgres \
  -v pgdata:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=123456 \
  -e POSTGRES_USER=app \
  -e POSTGRES_DB=appdb \
  postgres:17
參數 說明
-v <volume 名稱>:<容器內目錄> 掛載 volume；volume 不存在時會自動建立
-e <KEY>=<VALUE> 設定環境變數

⚠️ 密碼 123456 僅供學習示範，正式環境請改用更安全的方式（如 secrets 或 .env）。

4.3 Bind Mount

由使用者指定宿主機目錄，直接掛載進 container，不經過 Docker 管理的 volume。

docker run -d --name nginx \
  -v /home/user/nginx/conf:/etc/nginx/conf.d \
  nginx

將宿主機的 /home/user/nginx/conf 掛載到 container 內的 /etc/nginx/conf.d，不需要事先建立 volume。

💡 加上 :ro（如 -v <宿主機目錄>:<容器目錄>:ro）可設為唯讀，避免 container 修改宿主機檔案。

💻 Windows 上宿主機路徑可寫成 C:\Users\me\conf（PowerShell 可用 ${PWD}\conf 代表目前目錄）。注意：宿主機目錄不存在時，-v 會自動建立一個空目錄；若路徑拼錯，容易誤以為掛載成功卻是空的。

📌 掛載到 container 內已有內容的目錄時：Bind Mount 會覆蓋原內容；具名 Volume 在第一次為空時會先複製原內容進去。

4.4 三種方式比較

方式 需要建立 Volume 資料位置 適用情境
Volume 需要（或自動建立） Docker 管理的目錄 資料庫、正式環境資料
Bind Mount 不需要 自行指定的宿主機目錄 設定檔、開發時同步原始碼
容器可寫層 不需要 container 內部 暫存檔案

辨識方式：-v 冒號左邊是名稱 → Volume；是絕對路徑 → Bind Mount。

5. 構建自己的應用映像檔（Dockerfile）

Dockerfile 是一份文字腳本，描述如何一步步建出映像檔；每一個指令會產生一層（layer）。

5.1 常用指令

指令 說明
FROM <image> 指定基礎映像檔（每個 Dockerfile 的第一個指令）
WORKDIR <dir> 設定工作目錄，後續指令都在此執行（不存在會自動建立）
COPY <來源> <目標> 將建置目錄中的檔案複製進映像檔
RUN <command> 建置映像檔時執行指令（如安裝套件、編譯）
ENV <KEY>=<VALUE> 設定環境變數
EXPOSE <port> 宣告應用監聽的 container 埠（僅說明，不會自動映射，仍需 -p）
CMD [...] container 啟動時預設執行的指令，可被 docker run 後面的參數覆蓋
ENTRYPOINT [...] 固定的啟動指令，docker run 的參數會接在後面

💡 RUN 是「建置時」執行，CMD 是「啟動時」執行，不要混淆。

5.2 範例一：C# (ASP.NET Core) API

採用 multi-stage build（多階段建置）：第一階段用 SDK 編譯，第二階段只帶 runtime 與編譯結果，最終映像檔會小很多。

# ===== 階段一：編譯 =====
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src

# 先只複製專案檔並還原套件，讓 Docker 能重複利用快取
COPY MyApi.csproj ./
RUN dotnet restore

# 再複製其餘原始碼並發佈
COPY . .
RUN dotnet publish -c Release -o /app/publish --no-restore

# ===== 階段二：執行 =====
FROM mcr.microsoft.com/dotnet/aspnet:10.0
WORKDIR /app
COPY --from=build /app/publish .

# .NET 8 之後的 container 預設監聽 8080
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApi.dll"]

📌 MyApi 請換成自己的專案名稱；dotnet 版本標籤請與專案的 TargetFramework 一致。

5.3 範例二：React 前端（Vite）

同樣用 multi-stage：先用 Node 建置出靜態檔，再交給 nginx 提供服務，最終映像檔不含 Node。

# ===== 階段一：建置 =====
FROM node:22-alpine AS build
WORKDIR /app

# 先安裝套件（package*.json 沒變就會用快取）
COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

# ===== 階段二：用 nginx 提供靜態檔 =====
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80

📌 Vite 的輸出目錄是 dist；若使用 Create React App，則改為 build。

補充（常見需求）：

  • API 位址：Vite 的環境變數在建置時就寫死進靜態檔（如 import.meta.env.VITE_API_URL），container 啟動後無法再改。要換位址必須重新 build（可用 ARG VITE_API_URL 搭配 docker build --build-arg 傳入）。

  • React Router 重新整理出現 404：nginx 需要把找不到的路徑導回 index.html。新增 nginx.conf：

    server {
  listen 80;
  root /usr/share/nginx/html;
  location / {
    try_files $uri /index.html;
  }
}

    並在 Dockerfile 最後階段加上 COPY nginx.conf /etc/nginx/conf.d/default.conf。

  • CORS：前端（localhost:3000）呼叫 API（localhost:5000）屬於跨來源，C# API 必須設定 CORS，否則瀏覽器會擋下請求。

5.4 .dockerignore

與 Dockerfile 放在同一層，避免把不必要的檔案送進建置流程（加快建置、避免洩漏機密）。

# C# API
bin/
obj/
.vs/

# React
node_modules/
dist/

# 共用
.git/
.env
Dockerfile
.dockerignore

5.5 建置與執行

# 建置（最後的 . 是 build context，不可省略）
cd docker-demo1/backend
docker build -t my-backend:1.0 .

cd ../frontend
docker build -t my-frontend:1.0 .

# 執行
docker run -d --name my-backend  -p 5000:8080 my-backend:1.0
docker run -d --name my-frontend -p 3000:80   my-frontend:1.0
參數 說明
-t <name>:<tag> 為映像檔命名並指定版本標籤
. build context（建置目錄），COPY 的來源以此為根
-f <file> 指定 Dockerfile 路徑（檔名不是 Dockerfile 時使用）

驗證：瀏覽器開啟 http://localhost:3000（前端）與 http://localhost:5000（API）。

⚠️ 前端在瀏覽器執行，呼叫 API 時要用宿主機可存取的位址（如 http://localhost:5000），不是 container 名稱。container 名稱只有在 container 之間互連（同一個自訂 network）時才有效。

5.6 優化重點

  1. 依賴先複製、原始碼後複製：套件清單很少變動，這樣修改程式碼時可沿用快取，不必重新安裝套件。
  2. 使用 multi-stage：建置工具不進最終映像檔，體積更小、更安全。
  3. 選擇精簡的基礎映像檔：如 -alpine、-slim，並固定版本標籤，不要用 latest。
  4. 務必寫 .dockerignore。
  5. 減少 layer 數量：相關的 RUN 可用 && 合併。

6. Docker Compose

前面都是一個指令啟動一個 container，服務一多（API、前端、資料庫…）就要打一堆 docker run、docker network、docker volume。Docker Compose 用一個 YAML 檔描述整組服務，再以一個指令啟動或關閉。

📌 現在使用的是 Compose V2：指令是 docker compose（中間為空格，不是舊版的 docker-compose），檔案建議命名為 compose.yaml，且不需要再寫 version: 欄位。

6.1 docker run 與 Compose 對照

docker run 參數 Compose 欄位
--name container_name（通常省略，用服務名稱即可）
-p 8080:80 ports
-e KEY=VALUE environment
-v pgdata:/path volumes
--network networks（預設會自動建立一個共用 network）
docker build build
--restart restart

6.2 範例：C# API + React 前端 + PostgreSQL

專案結構：

docker-demo1/
├── compose.yaml
├── .env
├── backend/      # 內含 Dockerfile（見 5.2）
└── frontend/     # 內含 Dockerfile（見 5.3）

compose.yaml：

services:
  db:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: appdb
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d appdb"]
      interval: 5s
      timeout: 3s
      retries: 10

  backend:
    build: ./backend
    restart: unless-stopped
    environment:
      # 同一個 Compose 專案內，直接用「服務名稱」(db) 當主機名稱
      ConnectionStrings__Default: Host=db;Port=5432;Database=appdb;Username=app;Password=${DB_PASSWORD}
    ports:
      - "5000:8080"
    depends_on:
      db:
        condition: service_healthy

  frontend:
    build: ./frontend
    restart: unless-stopped
    ports:
      - "3000:80"
    depends_on:
      - backend

volumes:
  pgdata:

.env（與 compose.yaml 同層，Compose 會自動讀取，並用來替換 ${DB_PASSWORD}）：

DB_PASSWORD=123456

⚠️ .env 含機密，務必加進 .gitignore；123456 僅供學習示範。

6.3 重點說明

  • services：每個項目就是一個 container，服務名稱同時是 network 內的主機名稱（所以連線字串寫 Host=db）。
  • 自動建立 network：同一份 compose.yaml 的服務預設在同一個 network，不必手動 docker network create。
  • volumes（最外層）：宣告具名 volume，等同先執行 docker volume create pgdata。
  • build vs image：有自己的 Dockerfile 用 build，直接使用現成映像檔用 image。
  • depends_on：只決定啟動順序；加上 condition: service_healthy 才會等 healthcheck 通過，避免 API 比資料庫先啟動而連線失敗。
  • 環境變數的巢狀寫法：ASP.NET Core 以雙底線 __ 代表層級，ConnectionStrings__Default 對應 appsettings.json 的 ConnectionStrings:Default。

6.4 常用指令

在 compose.yaml 所在目錄執行：

docker compose up -d              # 建立並啟動全部服務（背景）
docker compose up -d --build      # 程式碼或 Dockerfile 有改動時，重新建置映像檔再啟動
docker compose ps                 # 查看服務狀態
docker compose logs -f [service]  # 查看 log（可指定服務）
docker compose exec <service> sh  # 進入服務的 container
docker compose stop               # 停止（不刪除）
docker compose start              # 啟動已停止的服務
docker compose down               # 停止並刪除 container 與 network（volume 保留）
docker compose down -v            # 連同 volume 一起刪除（資料會消失！）
docker compose config             # 檢查並顯示最終解析後的設定

⚠️ down -v 會刪除資料庫資料，執行前請確認。

6.5 常見問題

  1. 改了程式碼沒生效：Compose 不會自動重新建置，需加 --build。
  2. API 連不到資料庫：確認連線字串的主機是服務名稱 db，不是 localhost（container 內的 localhost 是它自己）。
  3. PostgreSQL 的 POSTGRES_PASSWORD 改了沒效果：這些環境變數只在第一次初始化資料目錄時生效；要重來需 docker compose down -v 清掉 volume。
  4. 埠號衝突：宿主機的埠已被占用時，修改 ports 左邊的數字。

7. 推送映像檔到 Registry

建好的映像檔可以推送到 Docker Hub（或公司內部的 registry），讓其他機器 docker pull。

docker login                                   # 登入 Docker Hub
docker tag my-backend:1.0 <帳號>/my-backend:1.0   # 加上帳號前綴（命名規則：<帳號>/<名稱>:<tag>）
docker push <帳號>/my-backend:1.0              # 推送
docker pull <帳號>/my-backend:1.0              # 在其他機器拉取

⚠️ 推送前確認映像檔內沒有機密（密碼、金鑰、.env）；一旦推上公開 registry 就可能被他人取得，即使事後刪除也無法保證。

8. 清理與疑難排解

8.1 清理磁碟空間

docker system df             # 查看 image／container／volume 佔用的空間
docker container prune       # 刪除所有已停止的 container
docker image prune -a        # 刪除所有未被 container 使用的 image
docker volume prune          # 刪除未使用的 volume（資料會消失！）
docker system prune          # 一次清除已停止的 container、未使用的 network 與懸空 image（不含 volume）

8.2 常見問題

狀況 排查方式
container 一啟動就退出 docker logs <name> 查看錯誤；container 的主行程結束，container 就會結束
port is already allocated 宿主機的埠被占用，換一個 -p 左邊的數字，或停掉占用的 container
name is already in use 同名 container 已存在，先 docker rm 或換名稱
連不到服務 確認有設定 -p；服務是否監聽 0.0.0.0（只監聽 127.0.0.1 時，外部連不到）
container 之間連不上 確認在同一個自訂 network，並使用 container／服務名稱，不是 localhost
改了 Dockerfile 沒生效 重新 docker build（必要時加 --no-cache），並確認使用的是新的 tag
permission denied（Linux） 目前使用者不在 docker 群組，或掛載目錄權限不足

8.3 除錯流程建議

docker ps -a                 # 1. 確認狀態（Up／Exited）
docker logs <name>           # 2. 看 log
docker inspect <name>        # 3. 檢查設定（Ports、Mounts、Networks、Env）
docker exec -it <name> sh    # 4. 進入 container 實際檢查
